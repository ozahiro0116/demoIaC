# 04. デモ進行台本（日本語・経営者トーク付き）

所要 12〜15 分。Review モード前提。各「★承認」が見せ場です。

---

## 0. 事前準備（開始15分前）
- ベースライン正常を確認（[`/`](https://app-web-sql-dev-eus2.azurewebsites.net/) が「正常」）。
- [chaos/chaos-nsg-block-sql.md](../chaos/chaos-nsg-block-sql.md) の注入手順を実行
  （NSG `AllowSqlOutbound` を Deny にして main に push）。
- 数分後にアラートが発火する状態にしておく。

---

## 1. つかみ（30秒）— 経営者向け
> 「金曜の夕方、セキュリティ強化のつもりでネットワークの送信制御を1行締めた。
> その変更が、本番の受発注システムとデータベースの接続を落としました。
> ——よくある事故です。ここから先は、**AI エージェントが人の代わりに原因を突き止め、
> 修正案をプルリクエストで出し、承認を経て自動復旧する**様子をご覧いただきます。」

経営インパクトの一言:
> 「受発注が止まると、**1時間あたりの逸失売上・SLA違約・信用毀損**に直結します。
> 平均復旧時間(MTTR)を人手の数十分から、**承認込み数分**に短縮するのが狙いです。」

## 2. 障害の発生（1分）
- ブラウザで `https://app-web-sql-dev-eus2.azurewebsites.net/` を表示 → **「障害 (Unhealthy)」**。
- 解説: 「名前解決は成功（プライベートIP 10.20.2.x が見える）。でも 1433 ポートに届かない。
  ＝ DNS ではなくネットワーク経路の問題、と画面が語っています。」
- Azure Monitor / SRE Agent のインシデント一覧に **新規インシデント**が出ていることを示す。

## 3. SRE Agent の自動調査（3〜4分）
SRE Agent のスレッドを開き、調査計画が立つ様子を見せる:
- 「Runbook に沿って **NSG → DNS → Private Endpoint** の順で確認している」
- 「接続リポジトリの Bicep を読み、`web-sql-network.bicep` の `AllowSqlOutbound` が
  **Deny になっている**ことを特定した」
- 根本原因がファイル名・行・直近コミットで示される点を強調。

経営者トーク:
> 「人間なら、まずアプリを疑い、ログを漁り、ネットワーク担当に問い合わせ…と数十分。
> エージェントは**構成と直近変更を相関**させ、数分で“どの1行か”まで指し示します。」

## 4. ★承認①：修正の実行（Review モード）（1〜2分）
- エージェントが「修正ブランチ作成 → `access: Deny→Allow` に戻す → コミット＆プッシュ → Issue 起票」
  を提案。**Continue（承認）** を押す。
- 解説: 「**人の承認なしには何も適用しません**。これがガードレールです。」

## 5. ★承認②：プルリクエスト作成（1分）
- エージェントが PR 作成を提案 → **承認**。
- PR が立つと **CI（bicep-ci.yml）** が走り、**What-If 差分が PR に自動コメント**される。
- 解説: 「変更の影響が**適用前に**可視化されます。『NSG規則 access: Deny→Allow』の差分だけ、と確認できる。」

## 6. ★承認③：人がマージ（ヒューマン・イン・ザ・ループ）（1分）
- レビュアー（あなた）が PR を確認し **Merge**。
- 解説: 「最終判断は人間。AIは“整った変更”をここまで運んでくれる。」

## 7. 自動再デプロイと復旧（2〜3分）
- マージ＝main への push で **CD（bicep-cd.yml）** が起動 → NSG を再デプロイ。
- ブラウザの `/` が数分で **「正常 (Healthy)」** に戻る。
- アラートが **自動解決（autoMitigate）** されることを示す。
- エージェントの **修復サマリ**（アラート／即時影響／恒久対策＝PRリンク／根本原因＝ファイル・行／
  現在の正常性／追跡＝Issue／次のステップ）を見せる。

## 8. 締め（1分）— 経営者向け
> 「検出 → 原因特定 → 修正PR → 承認 → 自動再デプロイ → 復旧確認。
> このループが、**ガバナンス（承認）を保ったまま**、Microsoft の標準スタック
> （Azure Monitor / GitHub / Bicep / App Service / SQL）だけで回りました。
> 属人化を減らし、夜間・休日でも**一次対応を自動化**できます。」
